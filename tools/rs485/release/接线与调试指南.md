## 1. 系统架构

```
 ┌──────────────┐     4线制      ┌──────────────┐    RS485(A/B)   ┌──────────────┐
 │  称重传感器   │ ─────────────> │   称重变送器   │ ──────────────> │  USB转485模块 │
 │  (电阻应变式) │  E+ E- S+ S-   │  (带24V供电)  │    A+ / B-      │              │
 └──────────────┘                └──────┬───────┘                 └──────┬───────┘
                                        │                                │ USB
                                    24V 直流                            ▼
                                   电源适配器                     ┌──────────────┐
                                                                  │  电脑 (上位机) │
                                                                  │  Python 程序  │
                                                                  └──────────────┘
```

**数据流向**：传感器把重量转成微弱电压信号 → 变送器放大 + 模数转换 + 换算 → 按 Modbus RTU 协议从 RS485 口发出 → USB转485模块转成 USB 信号 → 电脑上的 Python 程序读取寄存器。

## 2. 接线

### 2.1 供电部分（先接这个）

变送器需要 **直流 12–26V** 供电，请准备一个 **24V 直流电源适配器**。

| 电源 | 接到变送器 |
|---|---|
| `24V+`（正极） | `24V+` 端子 |
| `24V-`（负极/GND） | `24V-` 端子 |

> 💡 **变送器内部会自己输出 5V 激励电压给传感器**，所以传感器不需要额外供电。别再接一路电源过去。

> ⚠️ 通电前务必确认正负极没接反。接反可能直接烧变送器。

### 2.2 传感器 → 变送器（四线制）

| 传感器线色 | 信号含义 | 接到变送器 |
|---|---|---|
| **红** | 激励+ (Excitation+) | `E+` |
| **黑** | 激励- (Excitation-) | `E-` |
| **绿** | 信号+ (Signal+) | `S+` |
| **白** | 信号- (Signal-) | `S-` |
| **黄 / 灰**（屏蔽线） | 抗干扰屏蔽层 | 变送器**金属外壳的接地螺丝** |

> ⚠️ **线色不是行业统一标准！** 上面是常见约定，但不同厂家（尤其是国产传感器）线色可能不同。
> **务必以你手上传感器的说明书/标签为准。** 接错线最坏情况是传感器无输出，一般不会烧，但会浪费大量排查时间。
>
> 如果传感器只有 4 根线、没有屏蔽线，忽略屏蔽线那一行即可（但抗干扰能力会差一些）。

### 2.3 变送器 → USB转485模块

| 变送器 | USB转485模块 |
|---|---|
| `A+` | `A+` |
| `B-` | `B-` |

> ⚠️ **A/B 不能接反，否则完全无法通讯。** 而且不同厂家的 A/B 丝印定义有时是**相反**的 —— 这是 RS485 调试中最经典的坑。如果一切参数都对但就是没反应，**第一步就是把 A/B 对调试试**，不用怀疑人生。

USB转485模块插到电脑 USB 口后：
1. 打开「设备管理器」→「端口 (COM 和 LPT)」
2. 找到类似 `USB-SERIAL CH340 (COM3)` 的条目
3. **记下这个 COM 号**，等下要填进代码和串口助手

> 如果设备管理器里没有「端口」这一项，或者有黄色感叹号 → **驱动没装**。CH340 芯片的驱动去沁恒官网下，CP2102 的去 Silicon Labs 下。模块用的是哪个芯片看模块上的丝印。

### 2.4 通电前自检清单

- [ ] 24V 电源正负极确认没接反
- [ ] 传感器 4 根线按说明书接对（尤其 E+/E- 别和 S+/S- 搞混）
- [ ] A+ 接 A+，B- 接 B-
- [ ] 接线端子螺丝拧紧（虚接会造成数据跳变，很难查）
- [ ] USB转485 已在设备管理器里识别出 COM 口
- [ ] 变送器上电后指示灯正常（如有）

## 4. 调试步骤

### 4.1 第一步：用串口助手打通硬件

**推荐工具**：「友善串口调试助手」或 SSCOM（都免费）

**设置**：
1. 选对 **COM 口**
2. 波特率填你表里的值（先试 9600）
3. 数据位 `8`，停止位 `1`，校验 `None`
4. 切到 **HEX（十六进制）模式** —— 这一步很多人忘，忘了就会发出去一堆 ASCII 字符，永远收不到回复
5. **关闭其他占用串口的软件**（包括之前没关干净的 Python 程序）

**发送读取指令**（下面是完整帧，含 CRC 校验，可直接复制）：

| 场景 | 发送这串 HEX |
|---|---|
| 从站 1，读寄存器 0x9C40（40000）×2（**本项目变送器实测帧**） | `01 03 9C 40 00 02 EB 8F` |
| 从站 1，读保持寄存器 0（**最通用的起手式**） | `01 03 00 00 00 01 84 0A` |
| 从站 1，读保持寄存器 0，连读 2 个 | `01 03 00 00 00 02 C4 0B` |
| 从站 1，读寄存器 17 | `01 03 00 11 00 01 D4 0F` |
| 从站 1，读输入寄存器 0（功能码 04） | `01 04 00 00 00 01 31 CA` |
| 从站 111，读寄存器 17（原仓库代码的配置） | `6F 03 00 11 00 01 DC 81` |
| 从站 111，读寄存器 19（原仓库代码的配置） | `6F 03 00 13 00 01 7D 41` |

**帧结构说明**（以 `01 03 00 00 00 01 84 0A` 为例）：

```
 01    03    00 00    00 01    84 0A
 │     │     │        │        └──── CRC 校验（低字节在前）
 │     │     │        └───────────── 读几个寄存器（1 个）
 │     │     └────────────────────── 起始地址（0x0000）
 │     └──────────────────────────── 功能码（03 = 读保持寄存器）
 └────────────────────────────────── 从站地址
```

**正常回复长这样**：

```
 01    03    02    XX XX     CRC
 │     │     │     │         └──── 校验
 │     │     │     └────────────── 数据（2字节 = 1个寄存器）
 │     │     └──────────────────── 数据字节数
 │     └────────────────────────── 功能码（原样返回）
 └──────────────────────────────── 从站地址
```

> ✅ **只要能看到数据返回，硬件链路就通了！** 剩下的都是软件参数的事。
>
> 记下这个 `XX XX`，比如回复 `01 03 02 01 90 xx xx` → 数据是 `0x0190` = 400。
> 换上砝码再看数值变没变，就能确定是不是重量寄存器，也能算出换算比例。

### 4.2 第二步：跑 Python 程序

## 5. 故障排查表

### 5.1 串口助手阶段

| 现象 | 最可能的原因 | 解决办法 |
|---|---|---|
| **完全没回复** | ⭐ **A/B 接反**（头号原因） | 把 A/B 对调，重新上电试 |
| **完全没回复** | 波特率不对 | 依次试 9600 / 19200 / 4800 / 38400 |
| **完全没回复** | 从站地址不对 | 试 1，再试说明书上的值，再试 111 |
| **完全没回复** | 串口助手没开 HEX 模式 | 切到 HEX 模式再发 |
| **完全没回复** | 没供电 / 供电不足 | 量一下变送器端子有没有 24V |
| 回复 `01 83 02 ...` | **寄存器地址非法**（异常码 0x02） | 地址不在说明书范围内，换地址 |
| 回复 `01 83 01 ...` | 功能码不支持（异常码 0x01） | 换功能码：03 ↔ 04 |
| 回复乱码/半个帧 | 波特率或校验位不对 | 确认 8-N-1，波特率再核对 |
| **数据不停跳动** | 干扰 / 虚接 / 未预热 | 见下面 5.3 |
| 找不到 COM 口 | 驱动没装 | 装 CH340 或 CP2102 驱动 |

### 5.2 Modbus 异常码速查

回复帧的第 2 字节如果是 `0x80 + 功能码`（比如 `83`），说明从站返回了异常，第 3 字节是异常码：

| 异常码 | 含义 | 大概率原因 |
|---|---|---|
| `01` | 非法功能码 | 功能码用错了，03 换成 04 试 |
| `02` | **非法数据地址** | ⭐ 寄存器地址超出范围，查说明书 |
| `03` | 非法数据值 | 读的数量超了（比如想读 100 个寄存器） |
| `04` | 从站设备故障 | 变送器内部错误，断电重启 |
| `06` | 从站设备忙 | 发太快了，加大间隔 |
| `0B` | 网关目标设备无响应 | 超时，一般是接线或地址问题 |

### 5.3 数据跳变/不准

| 现象 | 原因 | 解决办法 |
|---|---|---|
| 数值小幅随机跳 | 正常噪声 | 软件做平均滤波（取 10 次平均） |
| 数值大幅乱跳 | 屏蔽线没接 / 接了但两端都接地 | 屏蔽线**只在变送器一端**接地，避免地环路 |
| 数值乱跳 | 附近有变频器/电机/大功率设备 | 远离干扰源，或换带屏蔽的双绞线 |
| 数值缓慢漂移 | 传感器温漂 / 未预热 | 上电预热 10–30 分钟再标定 |
| 数值恒定不动 | 传感器线接错（E/S 搞混） | 回第 2.2 节重新核对接线 |

### 关于原代码修复的内容

原仓库 `main.py` 有 4 个问题，都已修复（文件头有详细注释）：

1. **`print(c)` 是致命 bug** —— `c` 从未定义，每轮必抛 `NameError`，被裸 `except` 吞掉后打印一句假的 `Error while data from register`。**看起来像通讯失败，其实数据早就读到了。** 已改为 `print(val)`。
2. `setParameters()` 失败时返回 `None`，调用方不检查就继续用 → 后续崩溃被吞掉，表现为无限刷错误。已加判空和排查清单。
3. 裸 `except:` 掩盖真实故障。已改为打印异常类型和具体内容。
4. 硬编码参数集中到文件顶部配置区。

### 7.1 界面结构

### 7.2 无硬件先看效果（推荐第一次用）

双击 `运行.bat` 选 **2**（演示模式）：会自动起一个"模拟变送器"并连上，
曲线里能看到 8 秒一轮的穿刺曲线（静息 → 加载 → 刺穿跌落 → 回零）。

也可以手动玩：
1. 先开一个终端跑模拟从站：`.venv\Scripts\python.exe tools\mock_slave.py`
2. GUI 里「连接方式」选 **TCP 模拟**，端口 `5020`，点连接 → 开始采集

### 7.3 连真设备

1. 「连接方式」选 **串口**，选对 COM 口（先点「刷新」）
2. 波特率 / 从站地址 / 寄存器地址 / 比例 按第 3 节实测值填
3. 点「连接」→「开始采集」
4. 想存数据就点「开始记录」，CSV 自动存成 `force_日期_时间.csv`

> 默认参数已按本项目实测变送器预填：**从站 1，寄存器 `0x9C40`（40000）× 2，高字在前，有符号**。
> 换别的设备时再按第 3 节实测值改。

**采集参数（顶部）和串口助手（帧生成器）是两套独立设置，不会自动同步**，这是最容易踩的坑：

- 参数在点「开始采集」时才快照生效，**运行中修改无效**：先「暂停采集」→ 改 → 再「开始采集」。
- **从站地址改动后必须「断开」再「连接」**，链路里的地址是连接时写死的。
- 懒得手动抄参数：在「串口助手 → 帧生成器」里填好从站/地址/数量，点 **「填入采集设置」** 一键同步到顶部。
- 采集报 `读取失败` 时，日志里的错误会**附带实际发出的请求帧**（如 `请求帧: 01 03 9C 40 00 02 EB 8F`），
  和串口助手里能成功的帧逐字节对比即可定位；也可以勾「显示轮询流量」看完整收发。

> ⚠️ 串口是独占的：开着 GUI 的时候，SSCOM/串口助手是打不开同一个 COM 口的，
> 反过来也一样。想用外部串口助手，先在 GUI 里点「断开」。

### 7.4 内置串口助手（替代 SSCOM）

切到「串口助手」标签页：

| 功能 | 说明 |
|---|---|
| 预设帧 | 第 4.1 节那 6 条指令，直接「填入发送框」或「直接发送」 |
| 帧生成器 | 填从站/功能码/地址/数量，**自动算 CRC**（TCP 模式自动加 MBAP 头） |
| 发送框 | 勾 HEX 发十六进制；不勾就发 ASCII 文本 |
| 定时发送 | 按设定间隔重复发送（测稳定性用） |
| 日志区 | 所有收发帧带时间戳和耗时，TX 蓝 / RX 绿，一眼看清 |

> 勾上「显示轮询流量」还能看到采集线程发出的每一帧，相当于协议分析仪。

> pymodbus / minimalmodbus 两个库版本保留，作为交叉验证和备选。

**⚠️ pymodbus 版本陷阱（重要）**：
pymodbus 3.8 之后，读取函数里指定从站地址的参数名从 `slave=` 改成了 **`device_id=`**。
网上大量教程（和很多 AI 给的代码）还在写 `slave=`，在 3.15.0 上会直接报 `TypeError`。
本项目代码已按新 API 写好，不用改。如果以后升级 pymodbus 报参数错误，优先怀疑这个。

另一个坑：`read_holding_registers()` 在**串口断开时是抛 `ConnectionException` 异常**，不是返回错误对象。
所以不能只写 `if not result.isError()`，必须用 `try/except` 包住。本项目代码已处理。
